# Память AI-агента с Qdrant

Ассистент использует три уровня контекста. Последние сообщения передаются в `POST /api/assistant/chat` как short-term memory. Семантически похожие фрагменты текущего сеанса извлекаются из Qdrant как long-term memory. Актуальные числа, таблицы и результаты SQL должны вычисляться заново аналитической базой данных и не записываться в векторную память как источник истины.

## Переменные окружения

```bash
QDRANT_URL=http://localhost:6333
QDRANT_API_KEY=
QDRANT_COLLECTION=analytics_assistant_memory

# Необязательно. Если не задан, используется локальный детерминированный fallback-вектор.
OPENAI_API_KEY=
OPENAI_BASE_URL=https://api.openai.com/v1
EMBEDDING_MODEL=text-embedding-3-small
EMBEDDING_VECTOR_SIZE=1536
```

При первом запросе сервер создаёт коллекцию с cosine distance. Каждая запись содержит `sessionId`, текст диалога, тип (`conversation` или `fact`) и время создания. Запросы фильтруются по `sessionId`, поэтому память одного браузерного сеанса не смешивается с памятью другого.

## Запуск Qdrant локально

```bash
docker run --rm -p 6333:6333 qdrant/qdrant:latest
pnpm dev
```

Если Qdrant или embedding endpoint недоступны, чат не падает: он отвечает по встроенной базе знаний, а предупреждение записывается в server log. Для production рекомендуется использовать реальный embedding endpoint и ограничить доступ к Qdrant сетевыми правилами и API key.

## Очистка

Кнопка «Очистить историю» удаляет локальный идентификатор сеанса и не привязывает к нему новые сообщения. Серверное удаление ранее сохранённых точек Qdrant нужно выполнять отдельно владельцу окружения, например удалением всех точек с нужным `sessionId` через Qdrant API.
